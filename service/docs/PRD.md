# 리드요맵 제품 요구사항 문서 (PRD)

- 문서 상태: 재작성 초안
- 작성일: 2026-09-27
- 기준: 사용자와 합의한 MVP 방향, `demo-v0.26` 프로토타입, 현재 `service/` 구현
- 이 문서는 목표 동작을 정의한다. 현재 구현 상태와 다른 항목은 §10에 표시한다.

## 1. 제품 목적과 범위

리드요맵은 분양상담사가 지도에서 일할 현장과 모집 조직의 조건을 찾고, 모집공고자는 적합한 개인·팀을 모집하는 서비스다. 한 현장에 여러 조직의 공고가 있을 수 있다. 구직자는 **현장**을 찾은 뒤 **각 조직의 공고**를 비교한다. 공고의 금액과 지원 조건을 서로 다른 조직의 정보와 섞어 하나의 조건처럼 표시하지 않는다.

최소 기능 버전에서는 누구나 가입 없이 공개 현장과 공고를 열람하고, 공고에 공개된 전화번호나 카카오 오픈채팅으로 모집자에게 직접 문의한다. 공고를 올리는 사람만 이메일 인증 링크로 가입하고 비밀번호를 설정한다. 이후 이메일과 비밀번호로 로그인한다. 운영자는 현장·공고·모집공고자 상태를 관리한다.

### 이 문서에서 사용하는 용어

- **현장**: 지도에서 위치를 갖는 분양 사업지. 한 현장에 여러 상품 유형과 모집공고가 연결될 수 있다.
- **상품 유형**: 공고가 모집하는 계약 대상. 초기 선택지는 `아파트`, `오피스텔`, `상가`다. 유형 선택지는 데이터 구조에 마련하되, 확인되지 않은 상가 현장이나 공고를 자동 생성하지 않는다.
- **모집공고**: 한 모집자가 한 현장의 한 상품 유형에 대해 올리는 구인정보. 여러 타입의 RT가 다르면 공고 안에서 타입별 금액을 나눠 적는다.
- **RT**: 해당 상품 계약 1건당 모집 대상별 지급액. 팀 전체 금액과 개인별 금액은 서로 다른 입력 방식이다.
- **지원 상태**: 지원, 조건부 지원, 미지원, 미확인. `미확인`은 `미지원`이 아니다.

## 2. 사용자와 핵심 과업

| 사용자 | 핵심 과업 | 가입 |
|---|---|---|
| 분양상담사 | 지역·상품 유형·모집 대상·지원 조건으로 현장 검색, 공고 비교, 모집자에게 직접 연락 | 불필요 |
| 모집공고자 | 본인 정보 등록, 현장 선택 또는 현장 등록 요청, 공고 작성·수정·종료·재게시, 문의 응대 | 이메일 링크 인증 가입·비밀번호 로그인 |
| 운영자 | 현장 등록·수정·공개 상태 관리, 부정확한 공고 숨김·재게시 허용·삭제, 모집공고자 이용 상태 관리 | 운영 권한 필요 |

가입 없이 공고를 보는 사람에게 내부 메시지함을 요구하지 않는다. 전화·카카오 오픈채팅은 모집자가 선택한 공개 연락 수단이다. 전화번호는 모집자의 별도 공개 동의 후 표시한다.

## 3. 비회원 탐색 경험

1. 첫 화면은 지도 중심이다. 공개 중인 공고가 있는 현장을 마커로 표시한다. 군집을 선택하면 그 안의 현장이 보이는 범위로 지도를 확대하며 모달을 띄우지 않는다.
2. 검색·필터는 **공개 중인 같은 공고 한 건**을 기준으로 적용한다. 현장에 조건 A의 공고와 조건 B의 공고가 따로 있어도 A와 B를 모두 선택한 검색 결과에 그 현장을 넣지 않는다.
3. 기본 필터는 현장명/주소 검색, 지역, 상품 유형, 모집 대상(개인·팀장·본부장·팀 전체), 지원 조건이다. 지원 조건 필터의 초기 항목은 광고비, DB, 일비, 숙소, 식사다.
4. 지원 조건 필터는 기본적으로 `지원`만 일치시킨다. 사용자가 `조건부 지원 포함`을 켜면 `조건부 지원`도 일치시킨다. `미지원`과 `미확인`은 어느 경우에도 지원으로 취급하지 않는다.
5. 조건을 바꾸면 지도 마커, 현장 목록, 현장별 공고 건수를 **일치하는 공개 공고** 기준으로 함께 갱신한다. 필터 초기화가 가능하다.
6. 모바일에서 현장을 선택하면 지도 위의 작은 시트 대신 현장 상세가 화면 전체를 차지한다. 현장 요약과 공고 본문은 스크롤하고, 뒤로 가면 지도로 돌아간다. 데스크톱의 지도 중심 레이아웃은 유지한다.
7. 상세 화면은 현장 요약, `구인정보`(기본 탭), `현장 상세` 순서다. 현장 요약의 상품 정보는 해당 상품 유형이 명확할 때만 표기한다. 출처 원문 탭이나 외부 커뮤니티 원문 버튼은 노출하지 않는다.
8. 공고 카드에는 조직명, 모집 상품 유형, 타입별·대상별 RT, 실제 근무지, 지급 발생조건·지급시점·해약/환수 조건, 지원 상태와 세부 조건, 전화문의·카카오 문의(주소가 있을 때)를 표시한다. 금액을 확인하지 못한 대상은 임의로 `0원`으로 표시하지 않는다.

## 4. 모집공고 작성 경험

### 4.1 가입과 권한

- 누구나 가입 없이 탐색한다. 공고 작성은 이메일 링크로 인증하고 비밀번호를 설정해 가입한 모집공고자만 가능하다.
- 모집공고자는 담당자명, 조직명 또는 활동명, 본인 연락처와 필수 동의를 등록한다. 모집공고자 가입에 운영자의 별도 사전 승인은 없다.
- 공고는 모집자가 게시하면 바로 공개되며 운영자가 사후에 숨김·재공개·삭제할 수 있다. 본인은 자신의 공고만 수정·종료·재게시한다.

### 4.2 공고 입력 항목

| 묶음 | 필드와 규칙 |
|---|---|
| 현장·상품 | 기존 현장 선택 또는 현장 등록 요청. 공고마다 상품 유형 하나를 필수 선택(`아파트/오피스텔/상가`). 서로 다른 상품 유형을 모집하면 공고를 분리한다. |
| 모집 조직 | 실제 구인 주체의 조직명/활동명, 모집 대상(개인·팀장·본부장·팀 전체). 플랫폼명이나 타 조직명을 자동으로 대행사처럼 넣지 않는다. |
| RT | 행마다 계약 1건 기준 금액을 모집 대상별로 입력한다. 상품 타입/주택형은 선택 입력이다. 타입별 금액이 다르면 구분별 행을 추가할 수 있으며, 타입을 적지 않은 행은 공고당 하나만 허용한다. 입력하지 않은 타입명을 임의로 `공통`이라고 표시하지 않는다. `팀 전체` 단독 입력과 `팀장+개인` 개별 입력을 구분한다. 개별 금액의 합계를 표시할 수 있지만 이를 별도 지급액으로 중복 합산하지 않는다. `협의`는 명시적으로 표시한다. |
| 지급 조건 | 실제 근무지는 필수다. 지급 발생조건·지급시점·해약·환수 조건은 선택 입력이며, 비워 두면 `문의 시 안내`로 저장·표시한다. 실제 내용을 입력할 때는 계약 성립과 수수료 지급의 기준을 서로 구분한다. |
| 지원 조건 | 광고비, DB, 일비, 숙소, 식사 각각 `지원/조건부 지원/미지원/미확인` 선택. `지원` 또는 `조건부 지원`일 때 범위·금액·횟수·부담 조건 등을 설명할 수 있다. 그 밖의 내용은 별도 자유 입력란에 둔다. |
| 연락 수단 | 전화문의 번호 필수 및 공개 동의, 카카오 오픈채팅 주소 선택. 원문 수집처의 제3자 연락처를 자동 복사하지 않는다. |
| 게시 상태 | 게시 중/모집 종료, 운영자 숨김/삭제를 구분한다. 운영자 숨김·삭제 상태를 모집자가 우회해서 공개할 수 없다. |

외부 글이나 이전 공고의 자유 입력 설명에서 지원 여부를 자동으로 단정하지 않는다. 기존 공고를 구조화 필드로 이전할 때는 기본값을 `미확인`으로 두고 공고 작성자가 확인해 수정하게 한다.

## 5. 현장 정보와 상품 정보

- 현장은 지도 좌표·주소·명칭을 하나의 기준으로 관리한다. 사업지, 견본주택, 실제 근무지는 서로 다른 주소가 될 수 있으므로 각 의미를 구분한다.
- 한 현장에 아파트·오피스텔·상가가 함께 존재할 수 있다. 지도 마커는 현장 단위로 유지하되 공고 카드와 필터는 상품 유형 단위로 동작한다.
- 현장 상세의 분양가·규모·주택형·계약 조건은 상품 유형별로 다른 경우 분리해서 표시한다. 확인되지 않은 유형의 정보를 다른 유형에 재사용하지 않는다.
- 운영자는 현장정보를 생성·수정하고 공개 상태를 관리한다. 모집자는 목록에 현장이 없으면 등록을 요청할 수 있다.

## 6. 운영관리

- 운영자는 공고를 검색·필터하고 작성 조직, 현장, 상품 유형, 상태, 작성일과 핵심 RT·지원 조건을 목록에서 확인한다.
- 공고 숨김·재공개·소프트 삭제와 사유 기록, 모집공고자 정지·해제, 현장정보 수정·공개 상태 변경을 제공한다.
- 운영 조치는 이력에 남긴다. 목록이 커져도 찾을 수 있도록 검색·상태 필터·페이지 단위 조회를 제공한다.
- 운영자는 원문 출처 또는 확인 근거를 내부 기록으로 보관할 수 있다. 이를 이용자 공고 화면의 외부 원문 버튼으로 자동 게시하지 않는다.

## 7. 데이터·표시·필터의 공통 규칙

- 상품 유형, RT, 지원 상태는 화면 설명문을 파싱하지 않고 구조화된 값으로 저장한다.
- 공고 하나가 `광고비 지원`이고 다른 공고가 `숙소 지원`인 현장을 두 조건의 동시 충족 현장으로 표시하지 않는다.
- 공고가 비공개·모집 종료·운영자 숨김·삭제 상태이면 공개 지도 건수와 필터 결과에서 제외한다.
- `미확인`은 정보가 없다는 뜻이며 `미지원`이라는 주장으로 바꾸지 않는다. 모집자가 확인해 입력한 조건과 단순 수집·참고 자료를 구분한다.
- 전화문의는 공고 작성자가 동의해 등록한 번호로 연결한다. 다른 사이트에서 수집한 번호를 서비스 공고로 재게시하지 않는다.
- 사용자에게 보이는 금액은 상품 유형, 타입, 모집 대상, `1계약당` 기준을 함께 표시한다.

## 8. MVP에서 제외하거나 뒤로 미룬 기능

- 일반 분양상담사 회원가입과 서비스 내부 1:1 문의함: 초기에는 가입 없는 탐색과 직접 연락을 사용한다.
- 모집공고 사전 승인: 운영자 사후 조치로 대응한다.
- 구직자 지원 이력·채팅·알림·결제, 외부 커뮤니티 원문 재게시: 이 문서의 MVP 범위가 아니다.
- 검증되지 않은 상가 상품·모집공고의 자동 생성: 유형 지원과 실제 데이터 등록은 별개다.

## 9. 완료 기준 (핵심 시나리오)

1. 한 현장의 아파트 공고와 오피스텔 공고가 각각 다른 RT를 보여준다. `오피스텔` 필터에서 아파트 공고의 금액이 나타나지 않는다.
2. 오피스텔 39형과 45형의 팀 전체 금액이 다르면 각각의 행으로 표시된다. 팀 480만 원이 팀장 480만 원으로 보이지 않는다.
3. 광고비 지원과 숙소 지원을 동시에 선택했을 때, 두 조건을 **한 공고에서** 제공하는 현장만 지도와 목록에 남는다.
4. 광고비가 `조건부 지원`인 공고는 기본 광고비 필터에서 제외되고 `조건부 지원 포함`을 선택하면 나타난다. `미확인` 공고는 나타나지 않는다.
5. 모바일에서 현장 선택 후 요약과 모든 공고 내용을 화면 전체에서 스크롤해 읽고, 지도로 돌아갈 수 있다.
6. 모집자가 공고를 게시·수정·종료하면 공개 결과에 반영된다. 운영자가 숨긴 공고는 모집자가 수정·재게시해도 자동 공개되지 않는다.
7. 전화문의는 해당 공고 작성자가 동의해 등록한 번호로 연결한다. 카카오 주소가 없으면 카카오 버튼을 표시하지 않는다.
8. 기존 공고 이전 시 자유 입력 지원 문구는 보존하고 새 지원 상태는 `미확인`으로 둔다. 공개 내용을 임의 추정해 바꾸지 않는다.

## 10. 현재 구현과의 차이 및 작업 순서

이 표는 **2026-09-27 PRD 재작성 당시** `service/`의 차이를 기록한 것이다. 이후 로컬 구현 여부와 운영 DB 적용·배포 여부는 별도로 확인해야 한다.

| 우선순위 | 차이 | 필요한 작업 |
|---|---|---|
| P0 | 상품 유형이 없고 아파트로 고정 표시됨 | 현장·공고의 상품 유형 모델, 등록 선택, 카드 표시, 상품 유형 필터 |
| P0 | RT가 상품 타입별로 나뉘지 않음 | 타입별 RT 행 및 팀 전체/개별 금액 표시·검증 |
| P0 | 지원 조건이 자유 입력 문장 하나뿐임 | 지원 상태 필드, 세부 설명, 안전한 기존 데이터 이전 |
| P0 | 지도에서 지원 조건을 검색할 수 없음 | 동일 공고 기준 결합 필터와 결과 건수 갱신 |
| P1 | 지역 및 일부 운영 목록 탐색 기능이 제한적임 | 지역 필터·관리자 페이지 조회 개선 |
| P1 | 사업지·견본주택·근무지와 상품별 현장 정보가 분리되지 않음 | 주소·상품정보 표시 기준 정리 |

실제 데이터베이스 구조 변경, 기존 공개 공고의 상품 유형·RT 재분류, 운영 화면·약관의 상품 범위 문구 수정, 배포는 구현 단계에서 각각 검토한다. 현재 공개된 시험 공고의 금액과 상태를 이 문서 작성만으로 변경하지 않는다.

## 11. 남은 제품 결정

- 식사를 광고비·DB·일비·숙소와 함께 첫 출시의 지도 필터로 둘지, 구조화·표시만 먼저 할지. 이 초안은 **필터 포함**을 기본안으로 둔다.
- 지급 관련 조건을 공개하지 않는 모집자는 각 항목을 비워 둘 수 있다. 저장 시 `문의 시 안내`로 바꾸어 공고에 표시한다.
- 작성 중 공고를 공개하지 않고 저장할 `임시 저장`이 필요한지. 현재는 게시/모집 종료만 있으며, 시험 공고를 공개하지 않기 위한 수단은 별도 결정이 필요하다.
